# Backspace Fork 1.15.2 — capability map and design note

Status: **approved scope implemented and externally reviewed; review finding corrected; installed/audio/ARM64/HDR acceptance reported by the operator on 2026-10-25; publication authorized subject to final-commit CI/candidate checks**.
Baseline: `v1.15.1`, commit `297e84d76cd98f25abb54910d0db83ca7aa745ef`.

## Objective and confirmed requirements

The operator reports that HDR-to-SDR sharing in 1.15.1 works on their machine.
This is user-reported acceptance, not a new automated HDR/ARM64 measurement.
For **1.15.2** they request:

- Remove the yellow capture outline through supported Windows capture APIs.
- If borderless capture is unavailable or permission is denied, **block the
  affected capture**, rather than silently share with the outline.
- Offer an explicit way to **request permission again**.
- Completely remove Explore, including the external/global spaces network,
  and the Backspace project-hub page: their navigation, content and exclusive
  implementation, not merely the visible tabs.
- Keep only genuinely shared functionality required by retained features.

## Capability map

| Module id | Responsibility | Depends on |
|---|---|---|
| `borderless-capture` | Strict Windows native SDR capture, permission request/retry and safe failure | Existing native SDR capture and trusted source-selection lifecycle |
| `remove-project-hub` | Remove the Backspace hub and its exclusive desktop/mobile resources | Existing navigation, updater and source-offer boundaries |
| `remove-explore-directory` | Remove discovery and the external directory end to end; retain invite/join functionality separately | `remove-project-hub`; existing spaces/federation contracts |

Module specifications:
- [Borderless capture](2026-10-25-borderless-capture.md)
- [Remove project hub](2026-10-25-remove-project-hub.md)
- [Remove Explore and directory](2026-10-25-remove-explore-directory.md)

Build order: establish Windows borderless feasibility first, remove the hub,
separate retained invitation/join behavior from discovery, remove Explore and
the directory, then run combined validation and prepare versioned artifacts.
The capture module is otherwise independent of the two removal modules.

## Approach and alternatives

Use the existing Windows native path and official consent/border controls,
preserving the working FP16/tone-mapping/audio pipeline. Extract shared join
behavior before deleting discovery code. Remove exclusive runtime code, API
surfaces, workers, configuration controls, translations and workbenches.

Rejected alternatives:
- Hiding sidebar rows or leaving dormant directory requests/workers does not
  meet the operator's explicit complete-removal requirement.
- Continuing with a border after denial was offered and explicitly rejected.
- Registry hacks, patched Windows/Chromium binaries or disabling other apps'
  privacy indicators are not acceptable ways to remove the outline.
- Deleting all code named `explore` without tracing consumers breaks invitations
  and approval-based space entry, which currently share that module.

## Preservation and compatibility boundaries

- Preserve accounts, credentials, messages, existing spaces/memberships,
  uploads, drafts, explicit connections and invitation/approval flows.
- Do not mistake the global directory for federation itself. Do not remove
  manually connected remote spaces or disconnect their members.
- Preserve desktop updates, download/recovery paths, fork branding and the
  AGPL source/version offer outside the removed hub.
- Preserve migration history and existing database values for rollback; no
  destructive schema cleanup is included. Retired legacy columns may remain
  inert, but no active directory/hub implementation may depend on them.
- Update affected REST/shared types and docs deliberately. Old browser bundles
  may receive not-found responses for retired discovery APIs; retained invite,
  session and federation contracts must keep working.
- Keep the production desktop minimum disabled. This initiative does not
  authorize minimum activation, tag movement or replacing published assets.

## Stack, commands and conventions

Keep the current strict TypeScript/pnpm monorepo, React/Zustand web client,
Fastify server and Electron/Node-API/C++ Windows capture. No new dependencies
or packaging platform are approved by this design.

Run from the repository root, in the normal configured Node/pnpm environment:

```bash
pnpm build
pnpm typecheck
pnpm --filter @backspace/server typecheck:e2e
pnpm --filter @backspace/desktop build:ts
pnpm check:i18n
pnpm lint
pnpm -r test
node --test scripts/desktop-release-assets.test.mjs scripts/publish-desktop-release.test.mjs
node packages/desktop/scripts/build-sdr-capture.mjs --arch x64 --test
node packages/desktop/scripts/build-sdr-capture.mjs --arch arm64 --test
git diff --check
```

Run native tests on matching Windows hosts; a cross-build is not a runtime or
permission test. The root build remains ordered shared → server → web.
Use adjacent tests, existing i18n catalogs, typed error contracts and existing
UI controls. Do not weaken IPC sender/source authorization or Electron fuses.

## Combined acceptance and release boundary

1. All three module specifications pass their acceptance criteria together.
2. Actual packaged Windows capture demonstrates permission grant, denial,
   explicit retry, cancellation and borderless sharing without HDR regression.
   If supported APIs cannot meet this in the current installer, report the
   blocker rather than switch packaging or claim success without evidence.
3. Desktop and mobile have no Explore/Backspace hub navigation, pages, badges,
   discovery previews or exclusive resources. No directory traffic is made at
   boot, sign-in, invitation entry or ordinary use.
4. Existing invitation, request/approval, federation, updater/source-offer and
   core chat/call regressions pass. Both dev servers and the actual UI run.
5. Prepare all five manifests as 1.15.2 using the existing bump script, add
   versioned notes, verify CI/native builds and a complete read-only candidate,
   and obtain the required external review of the complete change.
6. The operator subsequently authorized publication and confirmed the real
   NSIS/permission, audio, ARM64 and HDR receiver tests. This is operator-reported,
   not independent assistant hardware verification; see the
   [validation record](../validation/2026-10-25-desktop-1.15.2.md).
   VM rollout and minimum-version activation remain unauthorized. Preserve
   immutable 1.15.1 and the existing verified-release/backup safeguards.

## Initial implementation gates (historical)

Implementation evidence and current release gates are recorded in the
[validation record](../validation/2026-10-25-desktop-1.15.2.md).

- Verify borderless consent behavior in the actual unpackaged/NSIS Windows
  distribution, including supported OS builds and denied/system-policy states.
- Exercise the actual Chromium-video-plus-native path, not just the native
  session: `stageScreenCapture` currently starts `getDisplayMedia` first.
  Denial must precede that acquisition, and a second Backspace-owned capture
  must not keep the indicator alive after the native property is configured.
- Confirm the exact old-route redirect/not-found handling without a catch-all
  SPA accidentally serving a removed JSON API as HTML.
- Trace references before deletion; shared boundaries identified so far are
  join requests, explicit remote connections, sticker instance-info reads,
  desktop update/download handling and the AGPL source offer.
