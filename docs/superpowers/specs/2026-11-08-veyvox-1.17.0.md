# Spec: Veyvox 1.17.0 rebrand and compatible replacement

Status: design approved by the maintainer; implementation plan awaiting approval.

## Objective

Rename this independent community fork to **Veyvox**, replace its product artwork
with the two maintainer-supplied images, and publish version **1.17.0** only after
the existing release gates pass. Existing installations must retain their accounts,
sessions, instances, preferences, messages, uploads and backups. Reuse existing
owners, migrations, icon generation and publication tooling, not a parallel app.

The user approved the compatible replacement approach, bilingual READMEs, upstream
credits, conditional commit/push/release, and subsequently the GitHub repository
rename plus description/topics. No production deployment or real-user data access
was requested.

## Baseline and existing seams

- Source baseline: current `origin/master`, `8ee1b4b4d15de7efeccab785cc528814e6e59d56`.
  It includes the 25-language PR and subsequent dependency/action updates. Work
  occurs in a separate `veyvox-rebrand` worktree; unrelated skills changes remain
  untouched in the original checkout.
- `packages/web/src/locales/`: 25 complete languages, 15 namespaces each.
- `assets/brand/` → `scripts/gen-icons.mjs` → web/PWA/desktop/tray icon outputs.
- Native startup: `main.ts`, `userDataMigration.ts`, `instanceUrl.ts`, l10n and
  preload; preserve their existing ownership and security boundaries.
- `scripts/bump-version.mjs`, desktop release inventory/verifier/publisher and
  `.github/workflows/{ci,release,native-sdr-capture,docker-publish}.yml` own release
  behavior. Current release assets are published from `bernardokcosta/backspace`.

## Scope and naming contract

- Public product name: `Veyvox`; canonical project/package slug: `veyvox`.
- Rename current product prose, titles, labels, notifications, About/download
  surfaces, manifests, build/package metadata, active docs and examples. Keep the
  independent Juno name, artwork, music, dubbing and rules unchanged.
- Historical/legal attribution, the actual Backspace keyboard key, and narrowly
  documented compatibility identifiers are exceptions to textual replacement.
  Never replace user content, stored identities, third-party names, immutable
  historical release records or original copyright holders.
- No blind global replacement of persistence keys, encryption identities,
  installer identifiers, IPC or federation fields. New visible branding must not
  create a clean profile, a second installation or a parallel server against the
  same database. Retain legacy technical identifiers where changing them cannot
  be proven safe; record the reason and regression for each exception.
- Target repository: `bernardokcosta/veyvox`, same owner, visibility and history.
  Do not transfer ownership, create a replacement repository, recreate the old
  slug, rewrite tags/history, or weaken release protection.

## Commands

Existing command owners are retained; package filters move consistently if renamed.

```sh
pnpm install --frozen-lockfile
pnpm gen-icons

pnpm typecheck
pnpm lint
pnpm --filter @veyvox/desktop build:ts
pnpm --filter @veyvox/server typecheck:e2e

pnpm --filter @veyvox/server exec vitest run --maxWorkers=2

node --test scripts/desktop-release-assets.test.mjs scripts/publish-desktop-release.test.mjs

```

Build order remains shared → server → web. Do not parallelize those builds.
Tests and startup use temporary storage/profiles, loopback and updater-off settings.

## Code style and interfaces

Keep strict TypeScript, current naming/style, existing helpers and no new dependencies.
For example, a renamed renderer bridge uses the existing typed security contract:

```ts
const bridge = window.veyvox ?? window.backspace;
```

This illustrates compatibility, not permission to expose Node, generic IPC or
unguarded operations. Each privileged action keeps its current sender/frame checks.
Any alias shares the existing implementation rather than creating a second flow.

## Verification and delivery boundaries

Always: preserve real data and secrets; test old→new, repeat startup, partial
failure, populated destination and fresh installation; keep all 25 languages;
inspect real rendered/icon outputs; run a full-scope external Sol review before
commit/release and fix concrete findings with affected checks.

Ask before: a conflicting target repository, destructive data reconciliation,
unrelated dependency upgrades, changing installation trust/signing requirements,
or any production deployment. Normal repository rename, metadata edits and the
validated 1.17.0 release are already authorized.

Never: delete/reset an existing profile/database to make migration pass, access
checkout `.env` or real runtime `data/` for tests, move existing tags, replace a
published release asset, bypass CI/security/asset checks, or claim unexecuted
platform/hardware migration acceptance.

## Success criteria

1. Veyvox is the visible product name everywhere current app-owned copy appears;
   every retained old-name reference is classified and justified.
2. Both supplied artworks are correctly named/imported; all icon families display
   the new V without old Backspace artwork or accidental transparency artifacts.
3. Upgrade fixtures retain sessions, settings, instances, account/installation
   ownership and server storage; failure cannot silently open an empty replacement.
4. English and Brazilian Portuguese READMEs describe the actual product/setup,
   link to each other and preserve upstream/contributor credit and AGPL notices.
5. GitHub name/description/topics and actual source/download/updater links agree;
   existing clients' update path is tested rather than assumed from redirects.
6. All workspace versions are 1.17.0, exact-commit CI and all release candidate
   platform/inventory gates pass, and the final release is verified remotely.
7. No production deployment or unrelated skills changes are included.

## Known constraints

- Supplied PNGs are 1254×1254. The standalone has alpha but visible stray edge
  pixels; preserve original bytes and inspect any deterministic derived cleanup.
- The repository currently has an empty About description/topics/homepage. No
  product website/domain was supplied, so do not invent one.
- Context7 is quota-exhausted. Ground CLI/library details in installed help/types,
  source and official documentation as necessary; do not upgrade to guess APIs.
