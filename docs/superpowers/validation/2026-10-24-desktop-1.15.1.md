## WGC worker and controlled-source evidence (newer local revision)

`--mode capture` creates and captures only its own known frameless test window;
it does not enumerate or save unrelated window pixels. The WGC FP16 source
passes through the real converter and managed texture transport, with sandbox
and context isolation on and renderer Node off. The successful x64 run produced
0/118/255 gray codes at 60×30 and 90×45 after a source resize/reconfiguration.
It also passed 100 immediate cancel/restart attempts, idempotent stop, a frame
callback exception and source closure, ending with zero retained output frames.

The initial closure test timed out: some providers stop frames without raising
WGC `Closed`. A bounded source-window validity check now handles this case.
Native pool tests also reproduced a capacity bug when a callback retained a
texture after releasing its frame id. Allocation permits now follow the last
physical texture reference, including callback/worker references, rather than
only the id map. Eight-thread reservation and retained-old-frame tests pass.

This is not a real HDR monitor comparison, a receiver test, sustained
high-resolution performance evidence or an ARM64 capture pass. Those gates
remain pending. The WGC/binding revision `addf30c6` passed native build/Electron
baseline/load on both x64 and ARM64 in CI `40143314431`.

## Main/preload integration (newer local revision)

The controller now binds a single native session to a focused main-frame grant
created only after an accepted Force SDR display-media selection. IPC validates
sender/frame, ownership, constraints and session id. Native module loading is
host-owned/lazy and never falls back from a missing packaged binary to a dev
path. Navigation, renderer loss and application shutdown revoke/stop capture;
alt-tab does not terminate an authorized live share.

The production-preload smoke was observed RED when the fixture still used its
old test-only preload. It now composes the actual compiled preload with a
reporting-only test bridge and uses the production controller/IPC registration.
The x64 controlled WGC video, resize, navigation and active-renderer destruction
checks pass, followed by the native cancellation/closure checks, with zero
retained frames. Navigation and destruction are asynchronous: the test waits
for the actual ended event rather than treating `window.destroy()` as sync.

Five production-preload unit tests cover early-frame/session/start-reply races,
stale frames, invalid metadata, parallel starts and failed VideoFrame transfer.
Fourteen controller/source-mapping/IPC tests cover the host lifecycle and authorization.
Together with prior tests and the pending-selection clock rollback regression,
all 20 desktop test files / 270 tests pass; TypeScript and repository lint pass.
The complete getDisplayMedia/audio/publication UI and real HDR/ARM gates remain
pending, and no release or minimum version has been activated.

Repeated local capture found two additional real resize defects before the host
integration commit. WGC can announce the new content extent while returning an
older smaller buffer; that frame is now dropped and the pool recreated, with
the strict GPU bounds check intact. Integer aspect-ratio scaling also replaces
floating-point/floor scaling: a deterministic native RED reproduced 156×78 →
89×44 instead of the requested exact 90×45. The corrected native test passes.
Ten consecutive complete production-preload capture smokes then passed,
including 1,000 aggregate immediate cancel/restarts and zero retained output
frames at the end of every run. These are small controlled-window tests, not
sustained HDR/1080p60 performance evidence.

CI `40145072184` for `43835389` then passed workflow validation, the complete
desktop unit suite, TypeScript and x64/ARM64 native build/Electron load checks.

Preparing setup integration exposed two more source-selection cases. A second
tile click must work after the first capture releases its thumbnail cache:
Force SDR now resolves the explicit id from a fresh **thumbnail-free** trusted
enumeration, checking focus/frame/generation before and after the async call.
The selected object, never an arbitrary renderer handle, answers the request.
The strengthened controlled smoke also proved that Electron can enumerate its
own known HWND as `window:<HWND>:2`, not only `:0`. TypeScript and C++ now
validate/preserve that numeric suffix without interpreting it as the HWND.
The mapping regression was observed RED, then the actual enumeration → native
capture → production-preload smoke passed, with empty thumbnail objects and
zero retained frames. Three new preselection tests bring the desktop total to
20 files / 273 passing tests. A fresh CI result for this follow-up is pending.
