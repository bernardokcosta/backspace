# Desktop 1.15.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The user selected native inline execution and later selected CI for ARM64 rather than installing global ARM64 tools. Do not delegate implementation without their selection.

**Goal:** Ship actual Windows HDR-to-SDR sharing and require desktop 1.15.1 only after a complete, verified release is available.

**Architecture:** Add a native Windows capture adapter behind the existing authorized screen-share flow, leaving Electron's renderer sandbox intact. A separate instance-owned compatibility policy blocks outdated ordinary desktop clients while preserving browser, bot and federation access. One release writer aggregates and verifies all artifacts before deployment and explicit policy activation.

**Tech Stack:** TypeScript strict, React 19, Zustand 5, Fastify 5, Electron 45, Windows SDK C++/WinRT/Direct3D/Direct2D, Node 24, pnpm 10.34.3.

**Spec:** [Approved initiative](../specs/2026-10-24-desktop-1.15.1-design.md), with its three module specifications.

## Global Constraints

- Force SDR is opt-in, saved per device, default off; never disable Windows HDR.
- Native capture ships for Windows x64 and arm64; other platforms retain current capture.
- Preserve `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`, RunAsNode disabled, EnableNodeCliInspectArguments disabled and OnlyLoadAppFromAsar enabled.
- Minimum desktop is **1.15.1**, configured by `BACKSPACE_MIN_DESKTOP_VERSION`, disabled by default; browser access stays available.
- Publish and verify all installers before enabling enforcement. Preserve `v1.15.0`; create `v1.15.1` once, at the reviewed release commit.
- Preserve fork identity, updater repository, source offer, production data and LiveKit.
- No incompatible dependency, cosmetic substitute for tone mapping, exposed native handle, silent uncorrected fallback or skipped hardware gate.
- Update affected subsystem documentation and every shipped language. Build shared → server → web in order.

## Review Focus

1. A native prototype that works only without isolation is not viable: native N1 must prove the real sandboxed preload/VideoFrame path.
2. Repeated cancel/restart while the renderer retains frames must not grow GPU resources: native N2 tests a process-wide bounded pool across sessions.
3. Already-open 1.14.2/1.15.0 sessions must not bypass the policy indefinitely through an existing call: minimum M1/M2 must prove the actual legacy transition before rollout.
4. Deferred sends must not run behind a visually blocking screen: minimum M3 moves lifecycle ownership, and tests pending-transfer and online callbacks.
5. A successful matrix must not mean an incomplete release: release R1/R2 verifies exact assets and both Windows updater entries before the public/production gate.

weaker implementation.
