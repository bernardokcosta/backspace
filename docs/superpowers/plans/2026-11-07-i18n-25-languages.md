# Backspace and Juno 25-language Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` for inline
> implementation, task by task. Subagent-driven implementation requires explicit
> user selection; this plan does not authorize implementer agents. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Translate the complete current product into the approved 25 languages,
with contextual review, selectable Automatic mode and reliable English fallback.

**Architecture:** Extend the existing i18n owner, catalogs, checker and native
localization rather than adding a framework or account preference. Separate
preference from effective language, validity from completeness, and text direction
from physical game coordinates. Keep Electron's CommonJS packaging independent.

**Tech Stack:** Strict TypeScript, React 19, i18next 26.5.11/react-i18next 17,
Zustand 5 for existing Juno preferences only, Electron 45, Vitest, Node scripts.

**Spec:** [Approved initiative](../specs/2026-11-07-i18n-25-languages.md),
including its runtime/content/layout module specs; user approved on 2026-11-07.

## Global Constraints

- Exactly 25 entries: `en pt es fr de it ru uk pl nl sv da nb fi cs ro tr ar hi id vi th ja ko zh`.
- Copy canonical native labels verbatim from the spec. Use `Português (Brasil)`;
  retain `pt`/`zh` storage codes and actual pt-BR-only dubbing/media editions.
- Current delivery: complete translations, not hidden fallback. Future features:
  English mandatory, missing targets allowed with English fallback and visible debt.
- Preserve current Juno rules, illustrated examples/scroll-spy, category meanings,
  independent preferences/volumes, 20% music base gain and foreground-only playback.
- No new dependencies, external translation service, new wire/schema contract,
  operating-system changes, production accounts/data or secret-file access.
- Node >=22.12, pnpm 10; sequential build shared → server → web. Native build is separate.
- Preserve all pre-existing uncommitted work on `feat/juno-settings`. Version stays
  `1.16.8`. Initial execution authorized no commit/push. The 2026-11-08 follow-up
  conditionally authorizes commit/push after complete acceptance; no tag, release,
  publication or deployment is authorized.
- The user subsequently approved execution inline. Track completed work in the
  validation ledger; unchecked steps remain pending, not implied complete by approval.

## Review Focus

1. Switching Automatic ↔ explicit with the same effective language must update the
   selector/persisted mode; runtime R3 tests cover this without a languageChanged event.
2. Late OS replies or lazy imports must not undo a newer choice or dev preview;
   runtime R3/R4 tests use deliberately inverted promise completion.
3. Missing namespaces or entire plural families must use correct English grammar,
   while malformed supplied translations fail; content C1 and runtime R4 own this.
4. An Arabic game inside an English app, and vice versa, must include portalled
   settings without mirroring seats/artwork; layout L1/L2 tests own this.
5. Native disk-write failure and focus/resume must preserve live Automatic behavior,
   without IPC from foreign frames or overwriting typed picker input; runtime R2/R5.

only after every content batch passes. All native/catalog contributions are
verified locally; batching does not authorize shipping partial languages.

R1 registers new languages unreleased. R2 mirrors those codes natively but keeps
unreleased codes ineligible for normal OS selection. Completion tooling compares
all supported codes, including unreleased. L4 activates all 25 only after content
and layout acceptance; this is local feature eligibility, not a release command.

the leading `pnpm` with


inputs. Native inspection is explicitly requested with `--include-desktop`;
do not accidentally make a normal web build depend on excluded desktop files.
