# Juno Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship an original 2–4 player Juno game inside the voice mosaic.

**Architecture:** Shared public contracts and legal-card helper; server-only
authoritative engine and bounded room registry; origin-aware REST/private
snapshots and WS invalidation; native React/SVG table in the existing mosaic.

**Tech Stack:** Existing TypeScript, Fastify 5, React 19, Zustand 5, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-05-juno-design.md`

## Global Constraints

- No dependencies, DB schema or federation relay changes.
- 2–4 players, seven cards each, 108-card deck, 45-second turns.
- 1,000 rooms; lobby/result expiry 15 minutes; game lifetime 2 hours.
- Route all game actions through channel origin and that host's user ids.
- Five-language catalogs; matte content and glass floating controls.
- No automatic git commits; preserve user work and runtime data.

## Review Focus

- Old responses after voice changes/logout must not expose another session's hand.
- Repeated/stale commands must not draw or play twice.
- Hidden cards must never appear in another player's or spectator's projection.
- Departures in either direction must not skip the wrong player or strand a turn.
- Focus/fullscreen/mobile controls must not hide the hand or intercept card clicks.
